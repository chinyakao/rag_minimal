# RAG 基礎筆記

RAG（Retrieval-Augmented Generation）是先從外部資料檢索相關內容，再把內容放進提示讓語言模型回答的做法。它讓模型能使用最新或私有的資料，並且能附上引用來源。

## 為什麼要切塊

語言模型的 context window 有限，而且整份長文件做成單一向量會讓語意被稀釋。把文件切成較小的區塊（chunk），每塊各自嵌入，檢索時才能精準找出相關段落。切塊太小會失去上下文，太大則會混入無關內容，因此 chunk size 與 overlap 需要用評估集實驗調整。

## 向量檢索

嵌入模型把文字轉成向量，語意相近的文字距離較近。檢索時把問題也轉成向量，以 cosine similarity 找出最相近的區塊。向量檢索擅長語意相近但用字不同的查詢，但對專有名詞、型號、錯誤代碼等精確字串可能表現不佳。

## 什麼是 hybrid search

Hybrid search（混合搜尋）同時使用關鍵字檢索（例如 BM25）與向量檢索，再把兩份排名合併。常見的合併方法是 RRF（Reciprocal Rank Fusion）：每份結果中名次越前分數越高，把各排名的分數加總後重新排序。這樣能兼顧精確字串匹配與語意匹配。

## 評估

檢索品質可以用 hit@k 衡量：正確的來源文件是否出現在前 k 個結果。生成品質則需檢查答案是否忠於引用資料、資料不足時是否拒答。每次調整參數後都應重跑評估，避免品質退步。
